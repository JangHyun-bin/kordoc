## 접근법

문자열 공백만으로 분리하는 방법은 머리행의 열 수와 칸 배정까지 해결하지 못한다. 별도 table model 도입은 이번 범위에 필요하지 않다. 기존 OCR의 내부 위치 근거와 여러 본문 행의 공통 빈 구간을 이용하고, 확인한 경계를 열 추론부터 칸 배정까지 전달하는 방식을 채택한다.

1. 정확한 분리 좌표를 수동 주입한 상한 실험으로 downstream의 재결합 여부를 확인한다. 이 결과는 실제 OCR 품질로 집계하지 않는다.
2. 기존 CTC 위치와 원본 픽셀의 빈 구간을 대조한다. 문자열 후처리 이후 위치 대응이 불명확하면 분리 근거를 사용하지 않는다.
3. 같은 표 후보의 서로 다른 본문 두 행 이상과 머리행의 위치 근거가 일치할 때 열 경계를 제안한다. 원본의 값 행은 두 개이므로 세 행 이상을 필수로 요구하지 않는다.
4. 확인한 경계는 간격 기반 그룹화로 재결합하지 않는다. 불명확한 후보는 기존 결과를 유지한다.
5. 실제 병합 머리행과 원문 글을 보존한다. 부분 배정으로 원문을 잃거나 중복시키는 후보는 적용하지 않는다.

## 제약과 완료 기준

- 내장 OCR의 무괘선 표부터 적용한다. PNG와 scan PDF의 공통 경로에서 처리한다.
- 공개 API, CLI, SDK 옵션과 IR schema를 추가하지 않는다. 내부 정보는 공개 JSON에 노출하지 않는다.
- 새 model, dependency, outbound 경로를 추가하지 않는다. 기존 정답·평가기·제외 모수를 변경하지 않는다.
- OCR을 끈 텍스트층 PDF는 위치 근거가 없으므로 새 분리 규칙을 적용하지 않는다.
- 원본에서 `단가 | 수량` 및 `1,300 | 2`, `2,500 | 10`을 복원한다. 두 품목의 barcode·금액 대응을 유지한다.
- `단 가`, 숫자 내부 공백, 병합 머리행, 여러 줄 품명, 본문·목록·주소, 해상도·기울기 변화의 반례를 검증한다.
- 원본 이외의 표본으로 일반화 여부를 확인한다. 처리 시간·메모리와 원문 누락·중복을 함께 검증한다.
- 실행 가능한 전체 test·typecheck·build를 통과하고 독립 review를 완료한다. corpus 부재는 통과로 표현하지 않는다.
- commit과 PR 본문을 준비한다. PR 생성, 원격 push, main 반영, 배포는 하지 않는다.

## 확인할 구현 범위

`src/ocr/engine.ts`의 위치 근거, `src/ocr/pdf-ocr.ts`의 좌표 변환, `src/pdf/text-line.ts`의 내부 type, `src/pdf/page-blocks.ts`의 두 변환 경로, `src/pdf/cluster-detector.ts`의 열 추론·칸 배정·원본 item 소유권을 확인한다. 실제 진단에서 더 작은 공통 fix가 충분하면 근거와 변경 이유를 ledger에 기록한다.
